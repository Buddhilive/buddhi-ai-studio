# Accessibility Protocol (A11Y.md)

> Adapted from Project A11Y.md (MIT License, Copyright (c) 2026 Felipe A. Carriço).

Accessibility is a non-negotiable **pre-condition for use**, not an optional polish. If a user cannot complete a task due to an accessibility barrier, the feature is **technically broken**.

Whenever generating, modifying, or reviewing frontend, UI, mobile, or design tokens (aligning with DESIGN.md):
1. **Consult the A11Y skill**: Load `.agents/skills/a11y/SKILL.md` before writing interface code.
2. **Resolve Compliance Profile**: Default to **Standard (AA)** (WCAG 2.2 AA / ADA / EAA). Shield (AAA) applies to government/healthcare; Launchpad (A) to rapid prototypes. Launchpad relaxes visual contrast but NEVER relaxes keyboard, focus, or semantic HTML rules.
3. **Lazy-Load Reference Guides**: Consult the §2.1 loading map in `.agents/skills/a11y/SKILL.md` to load only the specific guide (`.agents/skills/a11y/references/guide-*.md`) for components you are actively building.
4. **Follow the 19-Rule Contract**:
   - Reuse existing accessible components via `buddhi_search` (*Component Reuse*).
   - Record conformant choices in `A11Y-DECISIONS.md` (*Decision Memory*).
   - Log accepted WCAG deviations with risk owner, approver, and expiry in `EXCEPTIONS.md` (*Exception Memory*).
   - Check contrast via `buddhi scripts contrast` or the MCP `check_contrast` tool (*never estimate ratios*).
   - Run the static gate `buddhi scripts verify-a11y` via `terminal-runner` before delivery (*Release Evidence*).
   - Replicate Section 7 automated checks with an unprimed subagent to achieve `fresh-context` verification.
